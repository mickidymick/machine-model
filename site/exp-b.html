Two experiments · Frontier · 2026-08-10 and 2026-08-13

It changed the answers. It did not change the outcome.

Experiment A asked whether a measured machine artifact changes what a model says. It does, decisively — but only against measurement, because a session with nothing but web search matched a curated topology document exactly. Experiment B asked whether that converts into a faster run. It did not. The agent without the artifact produced the faster configuration, by 2.9%, at p = 6.3×10−8.

Experiment A — the artifact changes the answers

Fourteen questions with checkable answers, three fresh sessions, one arm each. web was told only the machine’s name and had search. declared got a curated document built from what the machine says about itself — hwloc, the node diagram, the ACPI tables. measured got our briefing.

Web search matches the curated document, exactly

web and declared score identically in every category. Everything we hand-assembled from the machine — the non-obvious NUMA ↔ GCD map, the 56-core low-noise reservation, even Slurm’s -S 8 — a session told only “you are on Frontier” found in the OLCF User Guide. Frontier is documented well enough that free search reproduces a curated topology summary. So the curated document buys essentially nothing, and the only gap this project may claim is declared → measured.

The result stated properly: hedging protects a model from missing information but not from wrong information. Where nothing is published, every arm declined cleanly. Where the ACPI SLIT is published and wrong, they repeat it as fact — and the one confidently wrong answer in the whole evaluation came from the tidy curated document, not from search.

Experiment B — but it did not make the code faster

Two agents, the same benchmark source, the same fixed problem, the same one-node budget. They differed in one file.

The ladder

Floor is ZeroSum’s naive default reproduced — one node, 8 ranks, 7 OpenMP threads, no -c. Ceiling is hand-tuned from every claim this project has measured. 5 configurations × 10 interleaved passes, 50 runs, 0 failures.

The pre-registered mechanism was worth nothing

The whole experiment was built around huge pages. Our briefing records a 2.4× page-size penalty at a ~32 MB working set, and craype-hugepages2M works by relinking, so it must be a build-time decision. That was the predicted source of the entire effect.

Isolated by a configuration identical to the control except for one added module load line: +0.06 s (0.2%), p = 0.062. Not significant.

Why: the number was right, the regime was wrong

The control considered and rejected the module, and said why:

the hot kernel streams 64 contiguous ~12 KB coefficient chunks per spline evaluation, so page walks overlap with the DRAM traffic they precede — this code is bandwidth-bound, not TLB-latency-bound, so the payoff is small.

It was right. Our 2.4× is a correct measurement — taken with a pointer-chase, dependent random access. miniQMC streams. The measurement was sound; the regime did not transfer.

And the briefing said so itself

Line 17 of the document the treatment arm was reading:

Conditions are part of every number. A latency measured on 4K pages, or a bandwidth measured across one of four network links, does not generalise to other conditions. The conditions are stated; carry them.

The caveat was present, in context, and the misapplication happened anyway. Stating conditions in prose is not sufficient to stop a number being used outside the regime it was measured in. That is a design finding about measured-machine artifacts, not merely a null result.

Our own hand-tuned reference was beaten

The ceiling encoded our measured NUMA claims as 4 ranks × 14 threads, one per domain. Both agents independently chose 8 × 7 on L3 boundaries, and both beat it. The treatment arm explicitly considered 4 × 14 — its own choice in an earlier round — and rejected it: one core per L3 group is OS-reserved, leaving exactly 7 usable per CCD across 8 CCDs, so 8 × 7 is the only geometry confining a rank to a single L3 and a single NUMA domain.

The ceiling is also the noisiest configuration in the set (sd 1.67% against 0.19–0.67% elsewhere).

The harness is measuring what it should

Floor → ceiling spans 2.09×, against ZeroSum’s published 2.33× (63.67 → 27.33 s) on the same benchmark and the same machine, with our floor reproducing their baseline shape exactly. Equal work was verified on all 50 runs — 56 walkers, recovered independently from ranks × walkers and from FOM × time / nelec3.

Method follows their section 4.1: n = 10 per condition in one allocation, interleaved in rotating order, decided by a Welch t-test rather than a ratio of single runs.

What is not established

The residual after removing huge pages is −0.86 s and significant, so something else makes the treatment arm slower. OMP_PLACES=cores vs threads, and BLAS linkage — -DBLA_VENDOR=All against an explicitly pinned libsci_gnu_* path — both differ. That residual is not attributed and should not be claimed without a one-knob run.

One benchmark, one machine, one configuration per arm. This is not “measured artifacts make code slower.”

Reading the two together

Experiment A is not undone by Experiment B. They answer different questions and the answers are consistent: the artifact reliably changes what a model says, and that did not convert into a faster run on this benchmark. The mechanism connecting them is the same in both directions — a fact is only as good as the regime it was measured in, and neither a published source nor our own measurement carries that regime with it by default.

Where a published number is wrong, A shows the artifact fixes it: 3/3 against 1/3 on the misleading-docs questions. Where a number is right but taken under a different access pattern, B shows the artifact actively misleads. Those are the same defect seen from two sides — context that travels separately from the number it qualifies.

And the honest deflation, which belongs in both: on a machine as well documented as Frontier, plain web search already reproduces a curated topology summary. The artifact’s value was never in restating what OLCF publishes.

What this supports

  1. Against measurement-only and misleading-docs questions the artifact wins decisively; against a well-documented machine, web search matches a curated declared summary exactly.
  2. On this workload the artifact’s contribution to runtime was negative and significant, and its pre-registered mechanism was worth nothing.
  3. The failure is regime mismatch, not bad data. Every number in the briefing is correct.
  4. The briefing’s own conditions field did not prevent the misuse.
  5. A control with no machine document reasoned to the better configuration from the source code, and beat our hand-tuned reference.

The design step this points to: a measured artifact should carry the access pattern under which each number was obtained as a first-class, matchable field — something a reader must reconcile against its own workload — rather than as prose it is asked to honour.
