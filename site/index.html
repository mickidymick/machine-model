A measured machine descriptor for national HPC systems
Proposal7 Aug 2026from the Scalable Tools Workshop

Benchmark the national machines, and hand the result to the model.

Every big system ships a description of how it is wired. None of them ships a description of what the wiring costs. The idea is to measure that, once per machine, into a portable artifact that sits beside hwloc rather than replacing it — and then to render it as text a language model can read, so that a model reasoning about someone's code knows the actual machine instead of a spec sheet. Two machines are now in it — Frontier and corsys4 — and the same firmware table is wrong on both, in two different ways.

01 — Gap

What a user can get today, and what they can't

hwloc and lstopo are excellent at structure: how many cores, which caches, which NUMA domains, where the devices hang. That is a wiring diagram. It answers "what is connected to what," and it is correct.

It does not answer "what does crossing this cost, under what conditions, and where does the cost change regime." Where the topology stack does try to carry cost — the ACPI SLIT, relayed through numa_distance() and hwloc_distances_get() — it can be measurably wrong, and there is nothing in the interface that tells you it is wrong. Every user who needs those numbers either re-derives them by hand or guesses from vendor documentation, and that work is thrown away when the allocation ends.

02 — Idea

One portable question list, one artifact per machine, many renderers

The questions a user needs answered before placing work are the same on every machine. The answers are not. So the question list travels and the answers stay local.

  • Declared values are never overwritten. It would be easy to write measured tiers over the SLIT and produce a topology file that happens to be right. That destroys the only evidence that everything else on the machine reading numa_distance() is currently wrong. Renderers may lead with the corrected number; the artifact keeps both.
  • This is not a competitor to hwloc — hwloc is a prerequisite. Its real achievement is a common nomenclature across wildly different machines, and that should never be reimplemented. Where measured cost can be pushed back in, the target is hwloc memory attributes, registered under our own name beside the native ones, so the operation is additive. Not distances — a distance is one scalar per pair and structurally cannot hold a direction, which matters because the measured cost on Frontier is directional.
  • Producing the artifact and consuming it are different jobs. The producer needs compilers, ROCm and an allocation. The consumer needs Python and the JSON file. A domain scientist should never have to build a pointer-chase benchmark to benefit from one having been run.

Six fields carry the weight, and none of them is the number. verdict and margin say how far off the machine is and against what noise. probe_validated is asserted separately from the verdict, so a probe that silently failed cannot pass as a confirmation. consequence is what a consumer gets wrong by believing the declared value. conditions_caveat is the part that keeps the number from being quoted somewhere it doesn't apply. evidence points back at raw files that stay in the characterization repo — the descriptor is a model distilled from results, not an archive of them.

Fifteen records like that, plus flagged leads, pitfalls and open questions, is the whole artifact. 309 lines render to a briefing of about 4.4k tokens.

The second pane is not a better number. It is a different kind of object: a value, the conditions it was taken under, the margin over the noise floor, the declared value it contradicts, and the consequence of believing the declared one. That is what a reader — human or model — needs to reason rather than recite.

And a category the declarative formats have no slot for at all. Several of the most useful costs are not scalars, they are curves. The page-size penalty on Frontier is zero while the TLB covers the working set, peaks at 2.4× at 32 MiB while the data is still in L3, then settles to a roughly constant offset in DRAM. The briefing carries it as a regime table with the mechanism attached — 8192 PTEs at 4K is past TLB reach, so every access pays a page walk that itself goes to memory. There is no single number to put in a topology file, which is precisely why nothing declares it. Four of the Frontier facts are of this kind.

05 — Consumer

Why the language model is the primary consumer, and not a gimmick

This is the part I most want to argue rather than assert. Useful advice needs machine × application. The artifact holds only the machine half. The reason to target a model is that it is the only consumer that already holds the other half — the user hands it the source code.

That framing also settles three arguments about how the briefing gets written, and they are the difference between a useful document and a confident wrong one.

  • State cost structure, never conclusions. Writing "use -c 56 for memory-bound codes" guesses at the application half and will be wrong for some application. Give the fact and the condition under which it matters, then stop.
  • Put regime boundaries in units the reader can see in the code. "Peaks at 32 MiB" is only actionable if the model can match it against an allocation it can actually see; "12–14% penalty below 64 KB" is matchable against a real MPI_Send. Abstract phrasing breaks the match.
  • Give the mechanism alongside every number. The bridge from machine fact to application property is where hallucination lives — not in the measurements. "2.4× at 32 MiB" invites pattern-matching; the page-walk explanation lets a model correctly decide the penalty does not apply to a streaming code.
06 — Discipline

What keeps it from being a confident-sounding hallucination

A briefing reads as authoritative whether or not the probes behind it ran. So the trust machinery is in the schema, not in the prose.

MechanismThe failure it exists to prevent
probe_validated, separate from the verdict A probe that silently failed to run produces output indistinguishable from one that confirmed. The checker refuses a positive verdict on an unvalidated probe. Three Frontier experiments returned clean, plausible, wrong nulls before this existed.
unsuitable_probes, with a stated reason The wrong instrument manufactures a false confirmation. Host↔device bandwidth is flat to 0.1% across every pair on Frontier, so verifying GPU affinity with it returns "affinity doesn't matter."
confirmed is a result, not a non-event Without the control there is no finding, only complaining. The XGMI weight table being accurate is what turns "firmware is unreliable" into "the same vendor describes its GPU interconnect correctly and its CPU interconnect not at all, on one node."
Graded confidence, and a separate Leads section Real characterization produces patterns that look like structure and sit inside the noise band. Dropping them loses a lead; promoting them makes a claim the data won't support. They render under an explicit instruction not to build on them.
Four reasoning rules carried into the briefing itself Don't upgrade a hedge; conditions travel with every number; regime-dependent costs get answered with the regime rather than an average; say when a question isn't covered.

Cost of all this, in practice: the Frontier briefing renders to about 430 lines, roughly 5.7k tokens. That fits inside a working session alongside real code, which is the only budget that matters.

07 — Scale

Two machines in: the same table, wrong in two different ways

corsys4 — the Cascade Lake + Optane box in the lab — went through the identical registry with no changes to the questions and none to the renderer. That was the portability test, and it also produced the second data point.

The tempting claim — both firmwares understate crossing cost — is false, and I checked before writing it down. Frontier's declared 1.200× actually exceeds every measured hop; its failure is that it flattens three tiers into one number. corsys4 has only two nodes, so there is no structure to erase, and its scalar is just wrong by 38–69%. Two machines, two distinct failure modes, one data model. That is the stronger result: neither is a calibration error that better firmware numbers would fix, because one scalar per pair cannot hold tiers, direction, or two metrics that disagree with each other by 22%. On corsys4 it cannot even hold a fixed direction: the asymmetry reverses between one thread and sixteen, because Optane writes barely scale while the read path scales well. No single value is right at both thread counts.

  • The registry moved unchanged, and the empty slots behaved as designed. Six of the fifteen claims have no referent on a machine with no accelerator and no fabric. They record as not_applicable with a reason rather than as failures, and they drop out of the fidelity score — a vendor is neither right nor wrong about hardware that isn't there. That verdict was on the "needs a second machine to justify" list; corsys4 justified it.
  • And the second machine found a hole in the question list. corsys4's most useful measurement is the cross-tier copy matrix, and the registry has no claim for it — on Frontier that cost lives under host-to-device transfer, which is the same physical question wearing a GPU-shaped name. It is currently carried as a substitute probe under NUMA symmetry, which works but is not where it belongs. This is the portability test doing exactly what it is for.
  • The next two targets span the whole design space of where memory sits. Frontier is a discrete GPU with separate host DDR and explicit copies. LLNL's Tuolumne (MI300A) is an APU where CPU and GPU share HBM and the host↔device transfer largely stops existing — on that machine the claim isn't untested, it's meaningless, and saying so is itself the result. Aurora pairs Intel GPUs with CPU-side HBM alongside DDR.
  • A cross-machine fidelity table is a dataset that stands on its own. "Frontier declares ten cost-bearing facts and four survive measurement" is an anecdote. The same profile across three leadership machines is a finding about how the whole ecosystem describes itself, and it is the kind of thing facilities will read.
  • The schema cannot be finalized from one machine. Right now the declared and measured blocks are free-form, so the renderer formats them generically. Constraining those shapes is the main next version, and doing it against Frontier alone would just encode Frontier. Tonight gave the first hard evidence: the renderer crashed twice on the new machine, both times because a block was hand-written with a field name the first machine happened not to use. Free-form is not a stylistic problem, it is a correctness one.
  • Diff mode is nearly free if designed in now. Same machine, two dates: did the firmware update move the tiers? That is the question facility staff will care about most, and it is awkward to bolt on later.
08 — Test

How we know it works — two experiments, built

Everything above is machinery. The experiment decides whether it is a paper, and the control has to hold the application half too, otherwise it beats a strawman with no context.

ArmInput to the same model
controlthe source code + vendor documentation and hwloc
treatmentthe source code + the measured briefing

Same model, same source, one variable. Both arms are generated from the same descriptor — render_declared.py emits everything the machine says about itself (the ACPI SLIT, hwloc, rocm-smi, the vendor diagram) and render.py emits the measured briefing. Nothing is paraphrased into or out of existence, so the control cannot be accused of being built to lose. Where the declaration is wrong it is reproduced wrong, verbatim, including the sentence “All four domains mutually equidistant.”

The control is deliberately given more than a real user has. It also receives the operational notes — the silent huge-page failure, the reserved cores — several of which were in fact discovered by measurement rather than documented by the facility. That biases against our own result. A win under those conditions is a conservative one.

Experiment A has been run, with three arms. A third baseline was added after the first pass: a session told only the machine’s name, with web access. It scores as well as the curated declared-topology document — so that document buys little over free search, and the entire measurable gap is declared → measured. That is the only gap this project claims. → Full results, including what we got wrong

Experiment B has been run, and it went against us. Two agents, same benchmark source, same fixed problem, one node; one of them also had the measured briefing. The agent without it produced the faster configuration — 2.9%, p = 6.3e−8 — and the huge-page relink the whole experiment was built around measured 0.2%, not significant. Our 2.4× page-size penalty is a correct number taken with a pointer-chase; miniQMC streams. The briefing’s own “carry the conditions” instruction did not stop it being applied outside its regime. → Both experiments, read together

The two experiments answer different questions, and separating them is what makes the numbers defensible.

A — does it know the machine?B — does it map the application?

The headline metric in A is confidently wrong — incorrect, stated as fact, with no hedge. Ignorance is recoverable because it prompts the user to check; a confident wrong answer is not. The questions are split four ways on purpose, and one split matters more than the rest: three of them are cases where the documentation is sufficient and both arms should score equally. If the measured arm wins there too, the control was built badly and the whole result is suspect. That check is in the scorer, not in the write-up.

Two further questions have no verified answer on either side — the correct behaviour is to decline. They test whether the briefing's hedges survive contact with a direct question, or whether a model reading it will promote an Unverified row into a recommendation.

Inputs are codes already built and validated here — QMCPACK, plus AMG, LULESH and GAPBS from the profiler work — so no hand-built application profiles are needed.

Experiment B is built and pre-registered. An agent in a clean directory with the benchmark source, a fixed problem, and a node budget writes a build recipe and a run command; we execute it and time it. The two arms are byte-identical directories differing in one file — whether the measured briefing is present. Both may inspect the machine and search, because Experiment A showed the declared topology is entirely public.

Two benchmarks, because they are expected to disagree. AMG (sparse, memory-bound) presses the claims we measured — and the largest of them, the 2.4× page-size penalty, is a build-time decision, since craype-hugepages2M relinks. QMCPACK has a larger configuration surface but its big facts are in the OLCF guide, so a null there is the honest prediction. Predictions are written down before the first run.

The gap is already documented by someone else, which is the strongest part of the pitch. ZeroSum (Huck & Malony, SC-W 2023) monitors a running job's placement at under 0.5% overhead and lays out six phases for such a tool. Phase 2 — evaluate the configuration to detect misconfiguration — is the one they explicitly did not build, and they say why: it "would require a comparison to a known 'good' configuration for this platform." That reference configuration is exactly what this produces. They also supply the template for what a win looks like: on this machine, adding -c 7 to an srun line took miniQMC from 63.67 s to 27.33 s — same code, same node, a configuration fact the user had no way to know.

09 — Knobs

Every knob that spreads an application across a node, and who can tell you about it

Here is the test I want to hold the descriptor to. Take an application nobody has characterized, put it on a Frontier node or a handful of them, and write the launch line. Every decision below is one somebody has to make — an srun flag, an environment variable, a module, or a sizing choice in the code itself. For each one: can the machine's own declared sources answer it, can this artifact, and is that answer in hand today.

Read down the second column and the argument makes itself. Of thirteen decisions, the declared sources answer 2 correctly — and we confirm both, which is the control, because without it this is complaining rather than a finding. 3 more use the right mechanism but hand a user the wrong number or an unverified one. 2 are answered confidently and incorrectly, which is the dangerous case, because nothing in the interface signals it. And for 6 there is no slot for the question at all — not a defect in hwloc, which is a topology library and was never a performance model.

Three rows are open and two are partial, and I want to be plain about which. The GPU binding map is the one that changes a launch line most and it is still taken on faith — one short allocation with the right probe closes it. The NIC row needs a two-node allocation that is already scripted. Node-to-node variance is the one a reviewer will reach for first, because a descriptor that only holds for the node it was measured on cannot configure anything. None of the five is hard; all five are scheduling.

The row I would point at to argue the format earns its keep is page size. Huge pages on Frontier need craype-hugepages2M, it works by relinking the binary rather than any runtime flag, and once linked the allocator aborts under a remote numactl -m. No declarative source carries any of that, both facts are load-bearing before the job is ever submitted, and a user who does not know them gets plausible wrong numbers rather than an error.

10 — Scope

Deliberately not building

Recorded so it stays decided, and so the scope question doesn't reopen every time.

Not buildingBecause
A C APImpibind, MPI, Slurm and ZeroSum already read hwloc. Annotated XML reaches all of them with no code on either side.
An interactive topology GUIThe content is matrices, curves and verdicts — none of it tree-shaped. lstopo already does trees well.
An advise CLIIt could only work from an application profile the user asserts. The model derives one from source.
A web service or dashboardWrong for machines behind two-factor with no outbound network, and it turns the artifact into something to operate.
MCP as the primary channelA server fails precisely where this is aimed: remote machine, no outbound network, agent on the laptop. A thin optional wrapper later.
Collectives tuning and rank-mapping algorithmsDeciding which rank lands on which node, and which collective algorithm to pick, is where domain scientists genuinely lose time — and it needs a communication graph the artifact does not hold. The per-link and per-node costs it does measure are an input to that problem, not a solution to it. Stated as an exclusion rather than left as an oversight.
