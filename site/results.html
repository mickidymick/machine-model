What does measuring buy, over what you can already look up?

Three arms, one model (Claude Opus 4.8, effort High), fresh session each, the same 14 questions with checkable answers. The arms are a ladder of increasing effort: what you get for free, what you get from running every query correctly, and what you get from measuring.

All three tie on the questions the documentation answers correctly. That is the check that makes the rest readable — if measuring had won there too, the comparison was rigged.

The web arm and the curated one are indistinguishable — identical in every category, 7 correct each. Everything we hand-assembled from the machine, it found in the OLCF User Guide: the non-obvious NUMA↔GCD map, the 56-core low-noise reservation, even Slurm’s -S 8 flag. So the declared arm buys almost nothing over free search — and the entire measurable gap is declared → measured. That is the only gap this project claims.

02 — Shape

Hedging protects you from missing facts, not from wrong ones

Where nothing is published, every arm declined cleanly. Where something wrong is published, they repeat it. Asked to rank the six NUMA domain pairs by crossing cost:

declared — the curated document

“All six pairs are equivalent. There is no cheapest or most expensive pair.”

measured — the artifact

“They are not equivalent” — then all six pairs in order, with the three-tier structure and two-tool corroboration.

The declared arm is not guessing. It is reporting the ACPI SLIT accurately. The SLIT is wrong.

The uncomfortable part. On this same question the web arm hedged — “I do not have measured per-pair latencies… absent a measurement I would treat all six as equal” — while the curated document did not. Handing a model a tidy, authoritative-looking document made it more confidently wrong than letting it search. Presentation conferred authority the data did not have. That finding cuts at us too: our own briefing is a tidy, authoritative-looking document.

03 — Calibration

Published, corroborated, and still unverified

One claim has two independent declared sources that agree — and two measurement attempts that could not discriminate it. We asked where to place a host buffer for GCD 0, and how confident it was.

web“Confidence is high — straight from the OLCF mapping table, not inference.”
declared“High confidence: two independent sources agree.”
measured“Confidence is low… below 8% GPU-latency variance and hasn’t been measured. If it matters, measure it.”

Same answer three times, one calibration out of three. Published reads as verified, and corroborated reads as verified — to everyone except the arm holding an artifact that distinguishes them.

04 — Audit

What we got wrong

Four of these were caught by scoring our own experiment or by a consumer reading the artifact. They are on this page because a result whose failure modes you cannot see is not a result.

  • The control was over-supplied — and it did not matter
    Five of six “operational notes” were our own discoveries, including NIC scaling measured that same afternoon. Notes now carry provenance and only documented ones reach the control. Re-running scored identically: 7 correct, 4 hedged, 2 wrong, 1 confidently wrong. The trimmed material was not load-bearing, so the first result was not an artifact of over-supply.
  • The scoring rubric hid most of the result
    Counting a hedge as success everywhere scored “honest but no answer” the same as “correct,” so both arms tied 4/4 on measurement-only questions where one answered and the other declined. A hedge now counts only where declining is the right answer.
  • Promoting a finding deleted it
    gpu.die_parity moved from flagged to observations; the renderer knew only about flagged. The finding vanished from the briefing with no error, leaving an open question referring to a result no reader ever saw.
  • The artifact contradicted itself, and a consumer caught it
    The cache entry claimed results “identical across all four CCDs.” The measured arm noticed that contradicted the eight OS-reserved cores — one per L3 region — recorded elsewhere in the same briefing. The hwloc XML confirms eight L3 regions; the curves were taken one per NUMA domain, of which there are four. The entry conflated the sampling unit with the hardware unit and quietly overclaimed coverage.
  • One question is badly worded
    “Should I tune to saturate memory bandwidth?” can be answered “no” for reasons unrelated to the fact being tested — the web arm said no because the work runs on GPUs. Right answer, wrong reason. Needs rewording before publication.
05 — Gap

The public record, enumerated by the search arm itself

Asked afterwards which questions it could find no source for, the web arm listed them unprompted: 

no published per-pair NUMA latency or directional measurement
no documented GPU-vs-host message-size crossover
no Frontier-specific read-vs-write bandwidth number
cache sizes come from the Zen3 datasheet, not the OLCF guide

That list is the artifact’s scope, written by something with no stake in the answer. It is a better argument for measuring than any claim we could make on our own behalf.

06 — Limits

What this does not show

One model, one effort level, one session per arm.Not blinded, not replicated. A shape, not a study.
Scoring is ours.We wrote the questions, the ground truth and the rubric. The per-question record is published so the calls can be checked.
No application was run.This measures what a model knows, not whether the resulting configuration is faster. That is the QMCPACK experiment, and it needs machine time.
One machine, largely one node.Whether any of it generalises is what Tuolumne and Aurora are for.
